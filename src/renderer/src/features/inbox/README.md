# 인박스

Ctrl+5 또는 사이드바의 인박스로 이동한다. 헤더의 인박스 버튼이나 Ctrl+K의
`인박스에 수집` 명령은 작은 수집 창을 연다. 텍스트·링크 입력, Ctrl+Enter 제출,
파일 선택, 텍스트/링크/파일 드롭을 지원한다. 클립보드 API와 감시 작업은 사용하지 않으며
사용자가 직접 붙여넣은 내용만 수집한다.

홈의 **인박스에 추가**는 별도의 간결한 `InboxQuickAddDialog`를 사용한다.
입력창 자동 포커스, Enter 저장, Escape/취소, 저장 중 표시, 실패 시 입력 보존을 제공하며
성공하면 닫고 안내한다. 기존 InboxStore에 `홈 빠른 추가` 출처로 저장하므로 전체 인박스에서 확인할 수 있다.
홈의 자유로운 낙서장과 별개이고 명령 실행이나 AI 요청을 수행하지 않는다.

항목의 원문, 종류, 출처, 생성 시각, 처리 시각과 이동한 유형을 userData/inbox.json에 보관한다.
파일은 경로만 저장하며 파일 내용을 읽거나 복사하지 않는다. 원본 열기는 명시적 클릭으로만 수행한다.
미처리·처리 완료·전체 필터와 내용·출처 검색을 제공한다. 처리 완료를 미처리로 되돌릴 수 있다.
삭제 확인은 인박스 항목에만 적용하며 원본 파일과 이동한 대상은 삭제하지 않는다.

메모 이동은 기존 NoteStore 저장 경로를 사용한다. 할일·일정·바로가기는 인박스 원문을 채운
기존 등록 폼을 열며, 취소하거나 저장에 실패하면 미처리로 유지한다. 저장 성공 후 처리 완료로
표시하며 원문을 남긴다. 할일 제목과 바로가기 이름은 각 대상의 길이 제한에 맞춰 초기화하지만
인박스 원문은 유지한다. 일정은 원문·출처와 참고 링크를 채운다. 일반 파일도 파일 바로가기로 등록할 수 있다.
대상 저장과 인박스 상태 기록은 서로 다른 저장소다. 대상 저장 후 상태 기록이 실패하면 안내를 표시하고
인박스 항목을 유지하므로 새로고침 후 직접 처리 완료로 표시할 수 있다.

main은 등록된 창/프레임과 요청 스키마를 확인한다. 서버에서 ID와 시각을 발급하며,
수집은 최대 50개를 한 번에 검증하고 모두 유효할 때 저장한다. 전체 2,000개·10MB,
내용 10,000자 제한, revision 충돌 검사, 직렬 임시 파일 교체로 기존 목록을 보호한다.

`model/inbox-store.ts`가 저장 상태를 관리하고 UI는 props/콜백으로 격리한다.
`app/model/use-inbox-actions.ts`에서 다른 feature의 공개 API와 기존 등록 폼을 연결한다.
검증: `pnpm test:inbox`, `pnpm test:shortcuts`, 타입 검사·lint·build,
`pnpm test:fsd`, Storybook 빌드와 관련 화면 검증.
